# Dock Preview

English | [简体中文](README.zh-CN.md)

A native Dock window preview app for **macOS 27.0 and Apple Silicon**. Built with Swift and AppKit, with SwiftUI settings. The app has no third-party runtime dependencies and makes no network requests. Licensed under the [MIT License](LICENSE).

## Install

Download the DMG from [GitHub Releases](https://github.com/Augustine-C/dock_preview/releases). Open it and drag **Dock Preview.app** onto **Applications**, following the arrow. Launch the installed copy from Applications.

The distribution is ad-hoc signed and is not notarized by Apple. See the [English installation guide](docs/Installation-EN.txt) or [Chinese installation guide](docs/Installation-ZH.txt) for first-launch and permission steps.

## Build and run

Use current Xcode command-line tools on an Apple Silicon Mac running macOS 27.0 or later.

```sh
./scripts/build.sh
open "build/Dock Preview.app"
```

The output is `build/Dock Preview.app`. The app lives in the menu bar and does not add its own Dock icon.

On first launch, Settings opens without requesting permissions automatically. Click **Accessibility → Grant Access** to enable window discovery, restoration, and closing. Grant **Screen Recording** for thumbnails; title cards remain available without it. Confirm permissions yourself in System Settings. If macOS requests an app restart, quit from the menu bar and reopen it.

Builds use ad-hoc signing unless a signing identity is configured. Rebuilding or changing the signature may require granting permissions again. To use your own certificate:

```sh
SIGNING_IDENTITY="Certificate name" ./scripts/build.sh
```

## Packaging and languages

```sh
./scripts/package-dmg.sh               # Build and create a shareable DMG
./scripts/package-dmg.sh --skip-build  # Package an existing build
```

The output is `build/Dock-Preview-<version>-arm64.dmg`. It includes the app, an Applications shortcut, the MIT license, and English and Chinese installation guides. A fixed Finder layout presents bilingual instructions and an arrow from the app on the left to Applications on the right.

Packaging requires Python 3. On first use, the script installs pinned Finder metadata tools into the ignored `build/dmg-tools` directory; these are not app dependencies. Artwork is generated by `scripts/make-dmg-background.swift`, and `scripts/dmg-layout.py` configures the layout.

Only the distribution copy is re-signed ad-hoc; the local build retains its signing identity. Distributed packages are not notarized.

The interface defaults to the system's preferred languages, supporting English and Simplified Chinese with an English fallback. **Settings → Language** allows a manual selection that applies immediately and persists across launches. System dialogs and other apps' window titles retain their own languages.

## GitHub Actions release builds

`.github/workflows/release.yml` runs on pushes to main, pull requests, and manual dispatches. It tests the core, builds the arm64 Release app, and produces the visual DMG, an app ZIP, and SHA-256 checksums using GitHub's `xcode-27` Apple Silicon runner. Downloads appear in the run's **Dock-Preview-arm64** artifact and are retained for 30 days.

Pushing a `v<version>` tag publishes the downloads to a GitHub Release after a successful build. The tag must match `CFBundleShortVersionString` in `Resources/Info.plist`, such as `v0.2.0`. Only the tag publication job has contents write permission; builds use read-only permissions. CI uses ad-hoc signing without certificates or additional secrets. Its output remains unnotarized.

## Usage

- Hover over a running app's Dock icon for 250 ms to preview its windows.
- Click a card to restore and switch to the window. Hover over its × button to request closing that window.
- When the app has no open or minimized windows, the panel offers **Quit App**. This sends a normal quit request and preserves the target app's confirmation flow. The button is unavailable when the empty state cannot be verified.
- Click the panel background to give it keyboard focus. Use arrow keys to select, Enter to switch, and Escape to hide it.
- Moving from the Dock icon into the panel keeps it visible. Leaving hides it after 200 ms. Normal Dock clicks are preserved.
- The menu bar offers Settings, Pause, and Quit. Settings includes hover delay, card width, excluded app bundle IDs, and login launch.
- Minimized, hidden, and other-Space windows are discovered through accessibility APIs. Windows that macOS does not expose may be unavailable. When a screenshot cannot be captured, cards retain their icon, title, or explicitly marked cached image.
- Switching between fullscreen apps and Spaces is handled by macOS and depends on the target app and system Spaces settings.

## Resource management

There is no idle polling or continuous recording. Mouse detection is capped at 30 queries per second; accessibility queries run on a dedicated serial queue with timeouts. While the panel is open, windows and visible thumbnails refresh at most every two seconds. Accessibility notifications can update the list sooner.

Single-frame capture uses `SCScreenshotManager` and `SCScreenshotConfiguration`, with at most two concurrent captures and a maximum image dimension of 640 px. The 32 MiB limit is the thumbnail cache budget, not the app's total memory limit. A byte-budgeted LRU cache evicts old images and clears on memory pressure. Hiding the panel stops scheduling, cancels the session, and discards stale results. Minimized windows are not restored to capture images. Real previews are never saved or uploaded.

Window operations bind to accessibility objects. Screenshots match by PID, title, and geometry; ambiguous matches receive no guessed image. Closing uses AXCloseButton/AXPress to preserve document confirmation dialogs. Detecting a modal window hides the preview and activates the target app.

## Tests and diagnostics

```sh
./scripts/test.sh
"build/Dock Preview.app/Contents/MacOS/DockPreview" --diagnose
open -n "build/Dock Preview.app" --args --demo
```

`--diagnose` reads permission status without prompting. `--demo` displays six synthetic windows; clicking or closing them does not operate real windows. Quit the demo instance before normal use. Demo mode verifies layout, not capture compatibility.

Measure CPU and RSS for a normal running instance:

```sh
pgrep -x DockPreview
python3 scripts/measure.py --pid <PID> --seconds 30 --mode idle --output build/idle-performance.json
python3 scripts/measure.py --pid <PID> --seconds 30 --mode six-real-windows --output build/preview-performance.json
```

CPU is calculated from accumulated CPU time over the sampling interval; 100% represents one CPU core. The limited precision of `ps` may report very small changes as zero. RSS is not equivalent to Instruments' physical footprint.

Performance logs contain timings and window counts, without window titles or screenshots:

```sh
log stream --style compact --predicate 'subsystem == "local.augustine.DockPreview" AND category == "performance"' --level info
```

`cards_ready_ms` measures window enumeration through card display, excluding the hover delay. `capture_batch_ms` records capture time separately. Repeat at least 30 warm-start samples before calculating P95.

See [VALIDATION.md](VALIDATION.md) for evidence and pending checks. Earlier local validation confirmed both permissions and Finder enumeration, and user testing of 0.1.7 confirmed cross-Space previews and switching. The complete app matrix and capture workload remain unverified. Measured idle RSS was about 102 MiB, slightly above the 100 MiB target.

## Stable local signing and window diagnostics

Signing reads `SIGNING_IDENTITY`, then the ignored `.signing-identity` file, and otherwise uses ad-hoc signing. Never commit signing configuration or certificates. Handle Keychain prompts yourself. Switching from ad-hoc to a development certificate may require granting both permissions again.

Generate a read-only window report from the authorized installed app. It does not restore windows, capture images, or include window titles:

```sh
open -n -g -W -a "/Applications/Dock Preview.app" \
  --stdout "$PWD/build/finder-report.json" --args --window-report com.apple.finder
```

The report distinguishes raw AXWindows, paged arrays, direct child windows, retained references, included windows, and ScreenCaptureKit windows. Compare reports from a normal desktop and a fullscreen Space for minimized state, errors, and counts. Use the same signed app that has permission; a separately compiled probe does not inherit its authorization.

LaunchServices starts this diagnostic. Running the binary directly from a terminal may attribute accessibility access to the terminal or parent process, reporting false even when the installed app has access.

When AXWindows omits other-Space windows, the app can read AppKit window menu items through public accessibility APIs to provide title cards. Selection targets the original menu item; closing is disabled without a real window object. Screenshots require a unique title on both sides of the match within the same process. This fallback depends on the target app exposing an appropriate window menu.
